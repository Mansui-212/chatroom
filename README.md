# Chatroom

一个用 Python 实现的多人聊天室。第一阶段只提供命令行客户端和 TCP 服务端；通信基于 TCP 长连接与自定义流协议。业务层会与传输层解耦，为后续接入 Vue 前端预留 WebSocket 网关。

> 当前仓库处于设计阶段，下面内容是开发约定和实施计划，聊天服务尚未实现。

## 目标与边界

第一阶段交付一个可在命令行运行的多人聊天室：

- 基于 TCP 的长连接，支持多个客户端并发连接；
- 支持昵称、聊天室群发、私聊、用户/房间查询；
- 正确处理 TCP 粘包与半包；
- 具有心跳保活、异常断开清理和基础错误响应；
- 数据先保存在内存中，后续可接入 SQLite 或 Redis。

Vue 浏览器不能直接使用原生 TCP。因此未来的 Vue 客户端会通过 WebSocket 网关连接，网关与 TCP 服务端复用相同的消息模型和聊天业务层。

## 架构

```text
CLI Client ── TCP 长连接 ──> Python Chat Server
                                  │
                    协议编解码 / 会话管理 / 消息路由
                                  │
                      房间管理 / 聊天业务服务
                                  │
                    内存数据（后续 SQLite / Redis）

Vue Client ── WebSocket ──> WebSocket Gateway ──> 同一业务服务层
```

服务端优先采用 Python 标准库 `asyncio`，以异步 I/O 管理长连接和广播，避免在最小可用版本引入不必要的框架依赖。

## 通信协议

TCP 是字节流，不保留应用消息边界。应用层使用**4 字节长度前缀 + UTF-8 JSON** 的帧格式来处理粘包和半包：

```text
┌──────────────────────┬──────────────────────────┐
│ 4-byte uint32 (BE)   │ UTF-8 encoded JSON body  │
└──────────────────────┴──────────────────────────┘
```

- 长度字段使用网络字节序（big-endian），值为 JSON 正文的字节数；
- 每帧正文必须是一个 JSON 对象；
- 服务端会限制单条消息大小（初始建议为 1 MiB），拒绝畸形或超长帧；
- TCP 与 WebSocket 传输方式不同，但使用同一套 JSON 消息语义。

### 消息模型

所有消息至少包含 `type`。与聊天相关的消息一般还包含 `room`、`content`、`sender`、`timestamp` 等字段。

```json
{
  "type": "chat",
  "room": "lobby",
  "content": "大家好",
  "timestamp": 1780000000
}
```

初始消息类型如下：

| 类型 | 方向 | 用途 |
| --- | --- | --- |
| `register` | 客户端 → 服务端 | 设置昵称 |
| `join` / `leave` | 客户端 → 服务端 | 加入或离开聊天室 |
| `chat` | 双向 | 发送/广播房间消息 |
| `private` | 双向 | 发送/接收私聊 |
| `rooms` | 双向 | 查询/返回房间列表 |
| `users` | 双向 | 查询/返回在线用户 |
| `ping` / `pong` | 双向 | 心跳保活 |
| `system` | 服务端 → 客户端 | 上下线、入房等系统通知 |
| `error` | 服务端 → 客户端 | 参数、权限或协议错误 |

## 命令行客户端

客户端使用交互式命令。普通文本默认发送到当前所在房间。

```text
/nick 张三             设置昵称
/join lobby            加入 lobby 房间
/leave                 离开当前房间
/msg 大家好            向当前房间发送消息
/pm 李四 你好          向指定用户发送私聊
/rooms                 查看房间列表
/users                 查看在线用户
/quit                  主动断开连接
```

## 实施阶段

1. **最小可用版本**：实现 TCP 服务端与 CLI 客户端、长度前缀协议、昵称、单个大厅群聊、多人广播和断线清理。
2. **聊天室能力**：实现创建/加入/离开房间、房间与用户列表、私聊及系统提示。
3. **稳定性**：加入 `ping`/`pong` 超时检测、每连接独立发送队列、消息大小和频率限制、异常包处理和服务端日志。
4. **持久化与权限**：使用 SQLite 保存用户、房间和最近消息；按需要增加账号、密码或 Token；需要多实例时使用 Redis 存储在线状态并广播。
5. **Vue 接入**：增加 WebSocket 适配层，保持 TCP 和 WebSocket 使用一致的 JSON 业务协议。

## 第一版验收标准

- 服务端启动后，多个终端客户端可以同时建立 TCP 长连接；
- 同一房间中的客户端可实时互相收到聊天消息；
- 退出或异常断开后，在线用户状态会自动更新；
- 人为拆分或合并 TCP 数据时，协议仍能正确还原每条消息；
- 慢客户端不会阻塞其他用户接收广播消息。
